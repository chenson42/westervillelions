## 1.57.0 — 2026-08-07

### Feature: Printable Member Directory

**Value:** Members asked for a directory they could hold — one that works at a meeting, in a car, or
on a kitchen counter, without a phone. The portal had a searchable directory on screen but no way to
print a usable roster, and it didn't show mailing addresses at all. This adds a proper printed roster
designed for readability rather than density, because the people most likely to want one on paper are
the ones least well served by a dense spreadsheet.

#### What's New

- **Print / Save as PDF** from the member directory. It uses the browser's own print dialog, whose
  "Save as PDF" destination produces the PDF — the same approach the monthly financial statements
  already use, with no PDF software involved.
- **A roster laid out to be read.** Two columns rather than three, names in 13pt bold above an 11pt
  near-black contact block, generous spacing, no gridlines or shading, and alphabetical jump-letters
  down the page. Entries never split across a column or page break. For the club's current 41 active
  members this comes to four pages — deliberately more pages in exchange for larger, cleaner type.
- **Mailing addresses now appear in the directory**, on screen and in print. A member without an
  address on file simply shows nothing there — no blank labels or stray commas.
- **Board members carry their position** as a small tag beneath their name on the printed roster.
- The printed sheet carries the club header, the date it was generated, and page numbers, so a roster
  found later can be dated at a glance.
- Members can already keep their own address current under Profile; that continues to feed straight
  into the directory.

#### Permissions

| Feature key | Required for |
|-------------|--------------|
| `members.view` | Viewing or printing the member directory |

**This closes a gap:** the member directory page previously had no permission check at all, so any
signed-in account could read every member's contact details — including an account with no role yet
assigned. The directory now requires `members.view`, checked before any member data is read from the
database. Every user holding any role already has this permission, so no current member loses access.
The gap mattered more once mailing addresses were added to the page, which is why it was fixed as part
of this work rather than later.

### Defect Fix: Site navigation appeared on printed pages

**Problem:** The site header — logo, Donate, Admin, Member Portal, Sign Out — printed across the top of
page 1 of anything printed from the site.

**Root Cause:** The shared page footer was excluded from printing, but the header never was.

**Fix:** The header is now excluded from print alongside the footer. This affects every printed surface,
not just the new directory: the board-ready **budget worksheet** and the **monthly financial statements**
have both been printing with the navigation bar on page 1, and no longer do.

**Testing:**
- [x] Verified against a real generated PDF — the printed page now opens directly on the document's own
      heading, with a regression test that fails without the fix.
- [ ] The budget worksheet and financial statements have not yet been re-printed to confirm; both are
      expected to improve, and are worth a check before the next board meeting.
