## 1.82.1 — 2026-09-25

### Defect Fix: A member could be recorded as contacted when nothing was sent

**Problem:** Two places recorded who had been emailed — the dues reminder history behind the
treasurer's "last reminded" badge, and the per-recipient log of event announcements. Both could
mark a member as contacted when the message had not actually been delivered.

**Root Cause:** The same fault corrected elsewhere earlier today, in two places it had been missed.
When mail is refused rather than failed — as it always is outside the live site — the send reports
success, and both records took that at face value.

These two were overlooked by an earlier sweep because that sweep looked for code writing to the
mail queue. These write to their own separate records instead: the same fault wearing a different
shape.

**Fix:**
- Both now record the true outcome, and a message that was never sent is recorded as not sent, with
  the reason attached.
- The treasurer's **"last reminded" badge now only counts reminders that genuinely went out.** A
  member whose reminder failed correctly shows as not yet reminded, so they are included in the
  next send rather than being quietly skipped — previously the badge reported them as contacted.
- Every attempted recipient of an event announcement still gets a record, successful or not; none
  are dropped.

**Testing:**
- [x] A refused send no longer records the member as contacted
- [x] A member whose only reminder failed shows as not yet reminded
- [x] A member with a later failed attempt and an earlier successful one shows the successful date
- [x] A genuine send still records exactly as before

### Infrastructure: Test fixtures that expire

**Background:** An end-to-end test depended on a Farmers Market event whose series ended
2026-09-26, and would have begun failing the following day. The same class of problem had been
found twice before and fixed both times by moving the date forward, which only postponed it.

**Changes:** The test now creates its own event with dates relative to the day it runs, and removes
it afterwards. There is no fixed date left to expire.

## 1.82.0 — 2026-09-25

### Enhancement: A count of statements waiting to be sent to the board

**Value:** Sending the monthly statement to the board is deliberately a decision someone makes,
not something the site does on its own. But nothing told the treasurer a month had become ready —
after finishing reconciliation, a statement could simply sit there unsent with no prompt. A month
that is ready but unnoticed is, in practice, a month not sent.

**Changes:**
- The admin sidebar's **Reports** entry now shows a count of statements ready to send, so it is
  visible from anywhere in the admin area rather than only on the Reports page itself.
- Only statements that can actually be acted on are counted — a month already sent never appears,
  so the count reaches zero and stays there until there is genuinely something to do.
- Nothing is shown when there is nothing waiting.
- Visible only to those who can send statements — Admin and Treasurer.

#### Known Limitation

The count only reaches a treasurer who is already somewhere in the admin area. Someone who
finishes reconciling and closes their laptop will not be prompted. If statements are found sitting
unsent for weeks, a reminder email — like the existing dues reminders — would be the next step.

### Infrastructure: One place decides whether a message was sent

**Background:** The code that sends email and the code that retries a failed one each had their own
copy of the logic deciding whether the mail provider had accepted a message. That check was added to
the retry path a day before the main one — and in that gap, every rejection on the main path was
recorded as a success. That single day's divergence is what allowed a month of email to disappear
unnoticed.

**Changes:**
- Both paths now share one piece of code for that decision, so the two cannot drift apart again.
- Behaviour is deliberately unchanged on both paths; this removes the possibility of future
  divergence rather than altering anything today.
