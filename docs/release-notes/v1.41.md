## 1.41.1 — 2026-07-28

### Security: Clear the Auth.js Critical/High CVEs

**Background:** The production dependency audit had been flagging 3 critical and 2
high vulnerabilities in the authentication stack (Auth.js / `next-auth`), plus a
high-severity denial-of-service advisory in a build-tooling dependency. A review
found these had survived earlier remediation attempts not because no fix existed,
but because two `pnpm.overrides` entries in the project were actively pinning the
dependency tree to the vulnerable versions.

**Changes:**
- Corrected the `@auth/core` override (0.41.1 → 0.41.3) and bumped `next-auth`
  (beta.30 → beta.32) and `@auth/drizzle-adapter` (1.11.2 → 1.11.3), clearing all
  five Auth.js advisories (configuration-error session handling, email-address
  normalization, and `getToken()` exception safety).
- Corrected the `brace-expansion` override range (`>=5.0.7` → `>=5.0.8`) to pull the
  patched version, clearing the denial-of-service advisory.
- The production audit (`pnpm audit --prod`) now passes with zero high or critical
  findings (down from 6).

**Testing:**
- [x] Typecheck, production build, and the full 578-test suite pass
- [x] Live credentials sign-in verified end-to-end (session resolves, gated admin
  page loads) — no change to the sign-in, session, or provider behavior; a
  same-line beta bump whose release notes match exactly the advisory fixes
- [ ] Google OAuth sign-in (couldn't be exercised in an automated environment;
  provider config unchanged) — worth a quick manual check after deploy

## 1.41.0 — 2026-07-28

Builds directly on v1.40.0's cause-level budgeting: a single cause can now hold
several labeled lines, so you can budget each beneficiary separately.

### Enhancement: Labeled Cause Budget Lines

**Value:** v1.40.0 let you break a giving category down by cause, but only one line
per cause. In practice a cause like *Hunger & Basic Needs* funds several distinct
organizations — WARM (Westerville Area Resource Ministry), Westerville Sharing &
Caring, and others — and the treasurer needs to budget (and account for) each one by
name. This lifts the one-line-per-cause limit.

**Changes:**
- **Multiple lines per cause, each with a label.** Under one category you can now add
  several lines that share a cause, each carrying a free-text **label** (the specific
  beneficiary or program). The label field autocompletes from labels you've already
  used elsewhere in the same entity, so "WARM" stays "WARM" and doesn't drift into
  variant spellings.
- **Grouped display.** The breakdown editor now groups lines under a cause header with
  a **per-cause subtotal**, the labeled lines nested beneath, and the category total
  below — so a category reads as *cause → beneficiaries → amounts*.
- **A label is optional.** You can keep one plain, unlabeled line per cause (a generic
  catch-all) alongside any number of labeled lines. Trying to create two lines with the
  same cause *and* label (including two blank labels) is blocked, with a message that
  names the cause.
- **Edit in place.** A line's amount and label can now be corrected directly, in one
  step — the previous behavior had to delete and recreate a line to rename it, which is
  gone. (A line's *cause* is set when it's created; to move a line to a different cause,
  remove it and add a new one.)
- **Approve/lock still applies.** Labeled lines are covered by the same year-end
  approve/lock — a locked budget can't have lines added, edited, or removed until it's
  unlocked.
- Seeding from prior years is unchanged (it proposes one line per cause; you split into
  labeled lines by hand), and existing v1.40.0 budget lines simply become the unlabeled
  "generic" line for their cause — nothing to migrate by hand.
