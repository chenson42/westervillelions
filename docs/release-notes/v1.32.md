## 1.32.0 — 2026-07-21

### Feature: Bank Statement Reconciliation (The Ledger)

**Value:** Until now, "reconciling the books" meant eyeballing a bank statement
and hand-toggling rows one at a time, with no proof the month actually
balanced. The Ledger now has a real reconciliation workbench — upload the bank
activity, match it to the books, and close the month only when it balances to
the penny.

#### What's New

- **Reconciliation sessions:** Admin → Ledger → Reconciliation. Create a
  session for a bank account and statement period (historical months
  supported — the statement backlog can be worked oldest-first), enter the
  statement's opening and closing balances, and upload a Chase activity CSV.
- **Parse and discard:** the CSV is parsed into bank lines stored in the
  books, tied to the entries they clear — you never need to keep the file.
  Verified against real Chase exports (199 of 199 real rows parsed cleanly).
- **Over-wide extracts are safe:** rows outside the statement period are
  flagged and ignored, re-uploading the same file adds nothing twice, and a
  transaction that's already been reconciled can never be matched again — the
  database itself refuses.
- **Manual matching:** match each bank line to its book entry through a
  searchable picker, or create a missing transaction (bank fee, interest)
  directly from the bank line — check numbers pre-fill for check debits.
- **Hard tie-out:** the running delta (opening + cleared vs closing) is always
  visible, and a session can only close when it balances exactly — enforced on
  the server, not just the button. Closing marks every matched transaction
  reconciled; the uncashed-checks list updates automatically.
- **Surgical reopen:** reopening a closed session (a stricter permission)
  reverts only that session's rows, and is blocked if a later month has
  already closed on the same account.
- Coming in a future update: automatic match suggestions and Zeffy
  payout-batch matching.

#### Permissions

Existing keys: `LEDGER_VIEW` to view, `LEDGER_RECORD` to upload/match/close,
`LEDGER_MANAGE` to reopen.

### Feature: Membership Application Email Alerts

**Value:** Applications used to land silently in the database, discoverable
only by checking the admin site. Now the club hears about every prospective
member the moment they apply.

#### What's New

- Every successful application through the public join form sends an email to
  info@westervillelions.org with the applicant's name, contact details, and
  member type, plus a link to the review page.
- Deliberately minimal contents: sensitive application details (date of birth,
  address, family information) stay behind the authenticated admin page and
  never travel by email.
- The applicant's experience is completely unchanged, and an email hiccup can
  never break a submission.

### Feature: Treasury User's Guide

**Value:** The treasurer's knowledge — how the books are organized, what the
compliance warnings mean, how the money flows, and even how to hand the bank
accounts to a successor — now lives in the app instead of one person's head.

#### What's New

- **Admin → Ledger → User's Guide** (also linked from the Ledger overview): an
  eleven-section guide covering the two-entity book structure, recording
  income/expenses/transfers (with receipts, waivers, check numbers, and public
  gift descriptions), dues, reimbursements, uncashed checks, reconciliation,
  reports, compliance, and settings.
- **Treasurer transition section:** the real-world Chase account handoff
  procedure — board minutes required for signer changes, two forms of ID
  (a credit card counts), treasurer as primary, who must attend, and the
  ~two-hour time budget.
- **Compliance calendar:** Form 990 due November 15, with the club's live
  990 determination shown right in the guide.
- **All 14 compliance guardrails explained**, each with what to do when it
  fires; the Zeffy/Activity-Fund routing policy documented (dues to the club
  account; donations land in the Activity Fund and move promptly to the
  Foundation).
- **Settings recap with an annual-review habit** built into the text.

#### Permissions

Any Ledger permission grants access (`LEDGER_VIEW` / `LEDGER_RECORD` /
`LEDGER_MANAGE` / `LEDGER_APPROVE`) — no new keys.

### Enhancement: HEIC Receipt Photos

**Value:** iPhones save photos as HEIC by default; the receipt uploader now
takes them directly.

**Changes:**
- HEIC/HEIF photos are accepted and converted to compact JPEGs in the browser
  (Safari and WebKit-based browsers, including iPhone). Browsers that can't
  read HEIC get a clear message with the workaround instead of a confusing
  upload error.

### Security: Dependency CVE Fix

**Background:** The pre-push audit caught four freshly-published
high-severity advisories in an image library bundled with the framework
(`sharp`/libvips, reached via Next.js).

**Changes:**
- Forced the patched version via a scoped package override; full test suite,
  build, and e2e verified after the bump.
