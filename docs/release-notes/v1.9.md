## 1.9.1 — 2026-05-06

### Fix: Toast Notifications & Member Link Restriction

**Value:** Toast notifications now appear across the entire app — previously they were silently dropped because the `<Toaster />` component was never mounted. Admins can now also link more than one user account to the same member record, matching the schema's original design intent.

**Changes:**
- Mounted `<Toaster richColors position="top-center" />` in the root layout so success and error toasts render
- Removed the 1-to-1 guard from `/api/admin/users/[id]/link-member` — multiple users can now link to the same member record
- Removed the same guard from the create-user endpoint for consistency
- Linking now verifies the target member record exists and returns 404 if not

## 1.9.0 — 2026-05-01

### Feature: Create User from Admin; Scroll-to-Attendance

**Value:** Admins can now create user accounts directly without requiring the member to self-register. Clicking "View all RSVPs →" on an event now scrolls directly to the attendance section on the edit page.

**Changes:**
- Admin → Users page has a new "+ Add User" button that opens a modal dialog
- Admins can set name, email, temporary password, and optionally link the new account to a member record on creation
- The "member" role is automatically assigned to all newly created accounts
- If a member is linked and no name is provided, the name is pulled from the member record automatically
- "View all RSVPs →" link on the admin events list now navigates directly to the `#attendance` anchor on the event edit page
