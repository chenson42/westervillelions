## 1.56.1 — 2026-08-07

### Defect Fix: "Budget notes saved." appeared at the top of printed budgets

**Problem:** Printing a budget shortly after saving its Notes & Assumptions put the on-screen
confirmation message — "Budget notes saved." — at the top of the printed page, above the
board-facing worksheet.

**Root Cause:** The toast container is mounted globally and positioned fixed at the top-center of
the viewport, and nothing excluded it from print. Any toast still visible when Print was pressed
was rendered into the page. This was never specific to budgets — any page printed within a toast's
lifetime would have included it. The budget worksheet is simply the page that gets printed
routinely, and save-then-print is the sequence that exposed it.

**Fix:** A print-media rule hides the toast container when printing, applied globally rather than
to the budget worksheet alone, so transient on-screen feedback can never appear in any printed
document.

**Testing:**
- [x] Typecheck and production build pass.
- [ ] Print/PDF render confirmed by the treasurer — this project's test suites do not exercise
      print stylesheets, so this was not machine-verified.

## 1.56.0 — 2026-08-07

### Feature: Ledger & Budget Search

**Value:** Answering a simple question — "what do we have on WARM, budgeted and spent?" — used to mean
opening the register, picking the right entity and fiscal year, scanning by eye, then repeating the
whole exercise on the budgeting page and comparing by hand. There was no search anywhere in the
Ledger; the register filtered only by entity and fiscal year. This puts one search box on the
treasurer's dashboard and answers both halves of that question at once.

#### What's New

- **A search box on the Ledger dashboard.** Type a name, a payee, a check number, a cause — it takes
  you to a full results page. The query lives in the URL, so a search can be bookmarked or pasted to
  someone else and it opens the same way for them.
- **Results grouped by what they are.** Transactions in one section, budget lines in the other, each
  with its own count, so you can see at a glance whether something is budgeted, spent, or both.
- **Dollar subtotals that don't lie.** Each group totals every match, not just the rows on the current
  page — so paging to page 2 never changes the number. Income and expense are totalled separately
  rather than netted against each other, because a search matching both would otherwise cancel out
  into something meaningless.
- **Advanced filters:** fiscal year, entity, fund, category, cause, amount (a single value matches
  exactly, two values match a range), date range, transaction status, and bank account. Fiscal year
  defaults to the current year with a one-click "All years".
- **Click a result and land on the row**, not just the right page — search scrolls to it and flashes
  it on the register or the budgeting drill-down. It won't spring open an editor you didn't ask for.
- **Budget search covers lump-sum lines too.** A category budgeted as a single figure — Rudolph Run
  expenses, Scholarships — is searchable alongside itemized cause lines, and is labelled "Lump sum /
  Not itemized by cause" so the two are never confused. A zero in the Budget lines section can be
  trusted to mean zero.
- **Typed punctuation stays literal.** Searching for `%` or `_` looks for those characters rather than
  behaving as a database wildcard.

#### Permissions

No new feature key. Search reuses the gates that already protect the underlying data, so it can never
surface a result the viewer couldn't already open.

| Feature key | Required for |
|-------------|--------------|
| `ledger.view` | Seeing the Transactions section of search results |
| `budget.view` | Seeing the Budget lines section of search results |

A user holding only one of the two sees only that section — and the other section is never queried,
rather than being fetched and hidden. Reaching the search page itself requires either key.

#### New Routes

- `GET /admin/ledger/search` — grouped search results with the advanced filter panel; all state is
  carried in query parameters (`q`, `fy`, `entity`, `fund`, `category`, `cause`, `bankAccount`,
  `amountMin`/`amountMax`, `dateFrom`/`dateTo`, `status`, `txnPage`, `budgetPage`).

Existing register and budgeting drill-down pages now honour a `?highlight=<id>` parameter, which
scrolls to and briefly highlights a row, then clears itself so a stale highlight doesn't survive a
refresh.
