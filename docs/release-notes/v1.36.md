## 1.36.1 — 2026-07-22

### Defect Fix: Record Transaction Defaults to the Current Fund

**Problem:** Opening "Record Transaction" from a specific fund's page (for
example the Administrative Fund) pre-selected the first fund in the list
instead of the fund you were looking at, so the fund had to be changed by hand
on every entry.

**Root Cause:** The form always defaulted its fund dropdown to the first fund,
ignoring which fund page opened it.

**Fix:** The dropdown now defaults to the fund whose page you opened the dialog
from — the Administrative Fund on the Administrative Fund page, and so on. The
entity-wide "All Transactions" view still defaults to the first fund, since no
single fund is in context there.

**Testing:**
- [x] Record Transaction on the Administrative Fund page defaults to
  Administrative Fund; on the Activity Fund page, to Activity Fund (verified
  end-to-end)

## 1.36.0 — 2026-07-22

### Enhancement: "Bill Pay" Payment Method & Menu Tweak

**Value:** Many club expenses go out through the bank's online Bill Pay, but
the payment-method choices only offered Check, Cash, Zeffy, Debit Card, and
Other — so those payments had to be logged as "Other." And with dues collected
in just one month of the year, Dues sat higher in the Treasury menu than its
day-to-day use warranted.

**Changes:**
- **"Bill Pay"** is now a payment-method option when recording or editing an
  expense (and when creating a transaction from a bank-reconciliation line).
  Because it's an electronic method, it also keeps these payments clear of the
  "prefer non-cash" compliance guardrail.
- The **Treasury menu** now lists Dues below Reconciliation, reflecting that
  dues collection is a once-a-year activity: Ledger, Reconciliation, Dues,
  Reports, Compliance, Donors, Ledger Settings, User's Guide.
