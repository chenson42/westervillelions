## 1.8.5 — 2026-04-29

### Feature: Suspend/Unsuspend User Accounts from Admin

**Value:** Admins can immediately revoke portal access for a user without deleting their account — useful for members who leave the club or need temporary access removed.

#### What's New

- **Suspend button** on the admin Users list — each row now has a Suspend / Unsuspend action alongside Manage Roles
- **Confirmed dialog** — suspension uses the `ConfirmDialog` component describing what will happen before committing
- **Status badge** — Active (green) / Suspended (red) shown in a new Status column; suspended rows have a subtle red background tint
- **Immediate effect** — suspended users are blocked at sign-in (credentials and Google OAuth) and on next JWT refresh; the auth system already checked `isActive` at both sign-in and token refresh, so no auth changes were needed
- **Self-protection** — admins cannot suspend their own account
- **Audit log** — suspend and unsuspend actions recorded to `permission_audit_log`

#### Files Added
- `src/app/api/admin/users/[id]/suspend/route.ts` — POST (suspend) / DELETE (unsuspend) endpoint, requires `ADMIN_USERS` feature
- `src/components/admin/suspend-user-button.tsx` — client component with confirm dialog

#### Files Modified
- `src/app/(dashboard)/admin/users/page.tsx` — fetches `isActive`; added Status column and suspend button per row

## 1.8.4 — 2026-04-29

### Security: Security Hardening and SEO Improvements

**Value:** Closes several low-severity security gaps found during a site audit and improves search engine discoverability for public pages.

#### Security Fixes

- **HTML escaping in contact email** — user-supplied `name`, `email`, and `message` are now escaped before interpolation into the admin notification HTML, preventing XSS via crafted contact form submissions
- **Turnstile CAPTCHA on registration** — the `/register` page and `/api/auth/register` endpoint now require a valid Turnstile token, preventing automated account creation attempts
- **Security response headers** — added `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`, `Strict-Transport-Security`, and `Content-Security-Policy` headers to all responses via `next.config.ts`

#### SEO Improvements

- **Open Graph tags** — added `openGraph` metadata blocks to `/mission` and `/programs` pages so social media previews render correctly
- **Sitemap** — `/programs` added to `sitemap.ts`
- **Event JSON-LD structured data** — event detail pages now emit `Event` schema markup (name, description, startDate, endDate, location, organizer, image) for Google rich results

**Files Modified:**
- `next.config.ts` — security headers added
- `src/app/api/contact/route.ts` — HTML-escape helper applied to name, email, message
- `src/app/api/auth/register/route.ts` — Turnstile verification added
- `src/app/register/page.tsx` — Turnstile widget added; submit disabled until token present
- `src/app/mission/page.tsx` — `openGraph` metadata block added
- `src/app/programs/page.tsx` — `openGraph` metadata block added
- `src/app/sitemap.ts` — `/programs` entry added
- `src/app/events/[id]/page.tsx` — `Event` JSON-LD block added

## 1.8.2 — 2026-04-29

### Enhancement: Signee Names Update Instantly on Signup

**Value:** Members no longer need to refresh the page to see their name appear after signing up for an event.

**Changes:**
- Signee badge list is now owned in client state by `SingleEventSignup` and `OccurrenceSignupList` — both components receive `currentUserName` and `initialSignees` as props and update the list optimistically alongside the count and button state
- Name is added to the list on signup and removed on cancel; reverts correctly on API error or 409 race condition
- Removed the separate server-rendered signee block from the event detail page; signees are fully managed by the signup components

**Files Modified:**
- `src/components/events/occurrence-signup-list.tsx` — added `currentUserName` prop; optimistic signee add/remove/revert
- `src/components/events/single-event-signup.tsx` — added `currentUserName` and `initialSignees` props; signee list rendered inside component with optimistic updates
- `src/app/events/[id]/page.tsx` — pass `currentUserName` and `initialSignees`; removed separate server-rendered signee block

## 1.8.1 — 2026-04-29

### Feature: Event Signups with Per-Occurrence Support

**Value:** Members can now sign up for specific dates of recurring events (e.g., monthly volunteer shifts) rather than the event as a whole. Admins have full visibility and can manually manage signups.

#### What's New

- **Per-occurrence signups for recurring events** — the event detail page shows all upcoming dates in the series; members can sign up for any individual date independently
- **Single-event signups** — one-time events with "Allow Signups / RSVP" enabled show a Sign Up / Signed Up / Full button with live attendee count
- **Optional capacity cap** — the existing max attendees field applies per occurrence; when the cap is reached the button shows "Full" and is disabled; race conditions are handled via a unique index (postgres error 23505 → 409)
- **Member signup visibility** — logged-in members can see who else is signed up: names appear inline on recurring occurrence rows and in a signee chip list on single events
- **Admin grouped view** — admin event detail now shows signups grouped by occurrence date in an expandable accordion; past occurrences are dimmed and collapsed by default
- **Admin manual signup** — admins can add any member to any event/occurrence directly from the admin event detail page, and remove existing signups with a Remove button
- **Label update** — "Requires RSVP" in the admin event form renamed to "Allow Signups / RSVP" with updated helper text

#### Files Added
- `drizzle/migrations/0028_event_rsvps_occurrence.sql` — adds `occurrence_date` column + two partial unique indexes to `event_rsvps`
- `src/app/api/events/[id]/signup/route.ts` — POST/DELETE signup endpoints (login required)
- `src/app/api/admin/events/[id]/signup/route.ts` — POST/DELETE admin signup endpoints (admin only, no requiresRsvp gate)
- `src/components/events/occurrence-signup-list.tsx` — client component for recurring event occurrence list with per-row signup buttons and optimistic updates
- `src/components/events/single-event-signup.tsx` — client component for single-event signup button with count display
- `src/components/admin/occurrence-rsvp-section.tsx` — admin accordion component grouping signups by occurrence with add/remove controls
- `src/components/admin/admin-event-rsvp-table.tsx` — client component for non-recurring event RSVP table with remove buttons and add-member form
- `src/types/events.ts` — shared TypeScript types: `OccurrenceRow`, `SignupApiRequest`, `SignupApiResponse`
- `docs/features/event-signups.md` — feature requirements doc
- `docs/features/event-signups-technical.md` — technical design doc

#### Files Modified
- `src/lib/db/schema.ts` — added `occurrenceDate` to `eventRsvps`
- `src/lib/events.ts` — added `generateOccurrences()` and `isValidOccurrence()` utilities
- `src/app/events/[id]/page.tsx` — fetch signees with user join; build occurrence rows; render signup UI conditionally; show signee list to logged-in members
- `src/app/(dashboard)/admin/events/[id]/page.tsx` — grouped occurrence view for recurring events; fetch member list; wire add/remove components
