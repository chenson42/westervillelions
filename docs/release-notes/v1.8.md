## 1.8.8 — 2026-04-30

### Feature: Admin User Edit Form; Name/Email Sync Between Users and Members

**Value:** Admins can now edit a user's name and email directly from the portal instead of running database queries. Changes sync automatically to the linked member record and vice versa, so the two tables stay consistent without manual coordination.

**Changes:**
- Admin → Users list "Manage Roles" link renamed to "Edit" to make the feature discoverable
- User detail page now has an editable name and email form above the role manager; validates email uniqueness before saving
- Editing a member's name or email in Admin → Members now syncs to the linked user account
- Editing a user's name or email in Admin → Users now syncs to the linked member record (name is split into first/last on save)
- `isActive` continues to sync from member to user when toggled (existing behavior)

<a name="187"></a>
## 1.8.7 — 2026-04-30

### Enhancement: SEO Audit Fixes — OG Tags, Dynamic Sitemap, ISR, CSP Cleanup

**Value:** A full SEO and security re-audit of the production site found several gaps. All medium and high priority items addressed.

**Changes:**
- **Open Graph consistency** — `og:site_name`, `og:type`, and `og:locale` added to all public pages (homepage, `/about`, `/events`, `/join`); Next.js shallow-merges `openGraph` objects so per-page blocks were dropping inherited layout values
- **Dynamic sitemap** — public event detail pages now included automatically from the database; previously only static pages were listed
- **ISR caching** — `/about`, `/mission`, and `/programs` now use `revalidate = 3600` (1-hour edge cache) instead of being fully uncacheable on every request
- **Permissions-Policy expanded** — added `payment`, `usb`, `accelerometer`, `gyroscope`, `magnetometer`, `display-capture` restrictions
- **CSP: Google Maps embed** — `https://www.google.com` added to `frame-src`; the Programs page map was blocked because the embed loads from `www.google.com`, not `maps.google.com`
- **CSP: Givebutter removed** — `https://static.givebutter.com` and `https://widget.givebutter.com` removed from `script-src` and `frame-src`; Givebutter is not used in the codebase
- **Footer** — Programs added under "Get Involved"

## 1.8.5 — 2026-04-29

### Feature: Suspend/Unsuspend User Accounts from Admin

**Value:** Admins can immediately revoke portal access for a user without deleting their account — useful for members who leave the club or need temporary access removed.

**Changes:**
- Suspend / Unsuspend button on the admin Users list with a confirmation dialog
- Active (green) / Suspended (red) status badge in a new Status column; suspended rows have a subtle red tint
- Suspended users are blocked immediately at sign-in (both credentials and Google OAuth) and on next JWT refresh
- Admins cannot suspend their own account
- Suspend and unsuspend actions recorded to the permission audit log
- Suspended users excluded from the "unlinked member record" warning count

## 1.8.4 — 2026-04-29

### Security: Security Hardening and SEO Improvements

**Value:** Closes several low-severity security gaps found during a site audit and improves search engine discoverability for public pages.

**Security fixes:**
- HTML escaping of user-supplied fields in the contact admin email, preventing XSS via crafted form submissions
- Turnstile CAPTCHA added to the registration page and API endpoint
- Security response headers added to all routes: `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`, `Strict-Transport-Security`, `Content-Security-Policy`

**SEO improvements:**
- `openGraph` metadata blocks added to `/mission` and `/programs`
- `/programs` added to sitemap
- `Event` JSON-LD structured data added to event detail pages for Google rich results

## 1.8.1 — 2026-04-29

### Feature: Event Signups with Per-Occurrence Support

**Value:** Members can now sign up for specific dates of recurring events (e.g., monthly volunteer shifts) rather than the event as a whole. Admins have full visibility and can manually manage signups.

**Changes:**
- Per-occurrence signups for recurring events — the event detail page shows all upcoming dates in the series; members can sign up for any individual date independently
- Single-event signups — one-time events with "Allow Signups / RSVP" enabled show a Sign Up / Signed Up / Full button with live attendee count
- Optional capacity cap — applies per occurrence; when reached the button shows "Full"; race conditions handled via unique index (postgres 23505 → 409)
- Logged-in members can see who else has signed up
- Admin grouped view — signups grouped by occurrence date in an expandable accordion; past occurrences dimmed and collapsed
- Admin manual signup — admins can add or remove any member from any event/occurrence
- "Requires RSVP" renamed to "Allow Signups / RSVP" in the event form

## 1.8.0 — 2026-04-29

### Feature: Community Programs Page; Mark Handled for Contact Submissions

**Value:** Visitors asking about glasses and plastic drop-off no longer need to contact the club — the Programs page answers it directly. Admins can now track who handled each contact submission.

**Programs page (`/programs`):**
- New public page listing two community drop-off programs: eyeglass donation (monthly collection to OSU/SVOSH) and plastic film recycling (drop-off at Pure Roots, back door)
- Each program card shows accepted/rejected item lists, a drop-off location callout, and a Google Maps embed for Pure Roots
- "Programs" added to the site nav between Mission & Service and Events
- Connect page updated with a callout directing visitors looking for drop-off info to the Programs page

**Mark Handled for contact submissions:**
- "Mark Read" / "Mark Unread" renamed to "Mark Handled" / "Mark Unhandled"
- Handled submissions display "by [Name]" attribution
- Handler name stored in a new `handled_by` column on `contact_submissions`
