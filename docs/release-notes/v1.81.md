## 1.81.0 — 2026-09-25

### Feature: Send the monthly financial statement to the board

**Value:** The Statement of Financial Condition already appears for members as soon as a month is
fully reconciled, but nothing told the board it was ready — the treasurer had to remember to
mention it. This adds a deliberate, one-click way to send it, without handing that decision to
an automation that could mail the whole board a wrong figure that cannot be recalled.

#### What's New

- A panel on the Ledger's **Reports** page listing each fund's months that are fully reconciled
  and ready to send.
- **Send to Board** emails a short summary — the fund, the month, the ending balance and net
  income — plus a link that opens that exact month's full statement. The detailed figures stay
  behind sign-in rather than living permanently in inboxes.
- **Corrected statements are handled honestly.** If the figures change after a statement has
  already gone out, the month reappears as *Corrected*, naming the date the earlier one was sent,
  so the board is not left holding numbers that have since been restated. A change that does not
  affect any total — an edited memo or a re-categorisation — will not prompt a pointless resend.
- The statement is signed by whoever currently holds the Board position of **Treasurer**, not by
  whoever clicked send. If nobody holds that position, the send is refused with an explanation
  rather than going out unsigned.
- A confirmation step naming the fund, the month and the destination before anything is sent.
- The same statement cannot be sent twice, whether from a double-click or two people acting at once.
- Only months from this release forward are offered, so nothing is back-mailed on the day it ships.

#### Permissions

| Feature key | Required for |
|-------------|--------------|
| `ledger.report_send` | Sending a monthly statement to the board (Admin and Treasurer) |

Viewing the panel needs only the existing Ledger view permission; a viewer without the send
permission sees the information but no send control.

### Defect Fix: A rejected email was recorded as sent

**Problem:** This is the remaining half of the outage described in
[1.80.0](v1.80.md#1800). Mail that the email provider *rejected* was still recorded as sent.

**Root Cause:** The email library reports an API-level rejection by **returning** it rather than
raising it. The application discarded that return value, so a revoked key, an unverified sending
domain, an exceeded quota or a suppressed recipient all looked identical to a successful send. The
retry path was corrected in 1.80.0; the main send path was not, until now.

**Fix:**
- A rejected send is now recorded as **failed** with the provider's actual reason, and is retried.
- Rejections that cannot succeed on a retry — an invalid key, a bad sending address — stop
  immediately instead of making three futile attempts. Anything unrecognised is still retried,
  because assuming an unfamiliar error is permanent risks abandoning a message that would have
  gone through.
- Combined with the failed-email count added in 1.80.0, a provider outage now becomes visible on
  the next visit to any admin page, rather than going unnoticed.

**Testing:**
- [x] A rejected send is recorded as failed, never as sent
- [x] A successful send is unaffected
- [x] Permanent and temporary rejections are handled differently
- [x] Mail is still never delivered from a non-production environment

### Infrastructure: One rule for claiming that a message was sent

**Background:** Four faults of the same shape came to light in a single day — code reporting a
message as sent when it had not been. One of them cost a month of undelivered club mail.

**Changes:**
- A recorded decision now governs both halves of the problem: a send helper may only record success
  for a message actually accepted by the provider, and any feature that keeps a permanent "sent"
  record must distinguish *delivered* from *failed* from *blocked*, rather than trusting a single
  success flag.
- One remaining instance of this fault, in donor acknowledgment letters, is tracked and not yet
  fixed.
