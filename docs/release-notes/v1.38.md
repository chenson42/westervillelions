## 1.38.0 — 2026-07-27

### Enhancement: Guided Budgeting

**Value:** The Ledger could already track spending against a budget on each
fund's report page, but building the budget meant typing every target into a
blank editor — and Lions clubs have to keep two self-balancing budgets, where
publicly-raised money may never fund club operations. This adds a guided way to
build next year's budget and to see, as you go, whether each fund is balanced
the way its purpose requires.

**Changes:**
- **New Treasury → Budgeting page.** Pick an entity (Club or Foundation) and a
  target fiscal year, then **"Seed from last year"** pre-fills every fund's
  budget targets from that fund's prior-year actuals — all funds at once, or one
  fund at a time — so you start from real numbers instead of a blank sheet.
- **Non-destructive by default.** Seeding only fills categories that don't yet
  have a target for the year; it never silently overwrites existing entries.
  Replacing existing targets is a separate **Overwrite** action that asks for
  confirmation and tells you exactly how many entries it will replace.
- **Live per-fund balance guidance** as you adjust the numbers, matched to each
  fund's purpose:
  - **Administrative** — flags if budgeted income doesn't cover budgeted expense.
  - **Activity** — flags if the fund doesn't net close to $0 (it's a
    pass-through clearing account).
  - **Charitable / Scholarship** — shows a "planned drawdown" note when spending
    exceeds income, since deliberately spending down reserves is legitimate
    there — no false warning.
- The guidance is **advisory only** — it never moves money between funds and
  never blocks a save. The existing per-fund budget-vs-actual reports are
  unchanged.

**Testing:**
- [x] Typecheck and full unit suite pass (36 new tests; `ledger.ts` at 100%
  statement coverage), covering the balance rules per fund kind, the
  seed-from-actuals mapping and empty-year fallback, and the fill-empty vs.
  overwrite decision
- [ ] Live-database click-through of the seed, overwrite-confirm, and
  first-year/no-prior-data flows — to run before the first real budgeting season
