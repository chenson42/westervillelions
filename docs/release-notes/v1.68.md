## 1.68.2 — 2026-09-01

### Defect Fix: Bank reconciliation silently dropped duplicate same-day deposits

**Problem:** Uploading a Chase statement for reconciliation could quietly drop legitimate
transactions. A treasurer uploading a statement with five separate "REMOTE ONLINE DEPOSIT # 1"
deposits on the same day, for the same amount, only saw one of the five in the session.

**Root Cause:** Each uploaded row was given an identity built from date, description, amount, and
check/slip number. Chase's export gives no per-transaction ID, and same-day batch deposits often
share all four of those fields — so multiple real, distinct deposits collapsed onto the same
identity, and the database's duplicate-row protection silently discarded every one after the
first.

**Fix:** Each row's identity now also accounts for its position among identical-looking rows
within the same file, so genuinely repeated same-day deposits are no longer treated as
duplicates. A statement upload that legitimately re-submits the exact same file is still
recognized as a repeat and doesn't double-insert.

**Testing:**
- [x] Unit tests confirm five identical-looking deposit rows produce five distinct identities
- [x] Unit tests confirm re-parsing the same file twice still produces matching identities (no
  double-insert on a retried upload)
- [x] Affected production session backfilled with the missing rows after verifying the fix

### Enhancement: Treasury navigation, dashboard, and reconciliation session defaults

**Value:** Reimbursements and Approvals existed as working pages but had no link anywhere in the
admin sidebar — reachable only by typing the URL directly. The admin dashboard also linked to a
dead page, and starting a new bank reconciliation required re-typing dates that are almost always
the same.

**Changes:**
- Treasury navigation now includes **Reimbursements** and **Approvals**, alongside Ledger and
  Budgeting
- The admin dashboard's Newsletter Subscribers card now links to the correct subscriptions page
- The admin dashboard now surfaces a **Pending Reimbursements** count in Needs Attention, for
  anyone with Treasury access
- Starting a new reconciliation session now defaults the statement start/end dates to the
  previous calendar month

## 1.68.1 — 2026-08-30

### Defect Fix: November's Board Meeting was scheduled on Thanksgiving Day

**Problem:** The 2026–27 meeting schedule listed the November Board Meeting on the 4th Thursday of
the month — 2026-11-26, which is Thanksgiving Day. The club doesn't meet that day.

**Root Cause:** The board's meeting night moved from the 4th Tuesday to the 4th Thursday partway
through the year, and that change was applied mechanically across every month without checking
each date against the calendar — November's 4th Thursday happened to land on the holiday.

**Fix:** November's Board Meeting is now a one-off exception on the 2nd Thursday, 2026-11-12,
instead of the 4th Thursday. Updated everywhere the schedule appears: the events calendar, and the
welcome packet's meeting-schedule table (both the member and presenter decks).

**Testing:**
- [x] Verified no other month's Board Meeting falls on a recognized holiday
- [x] Confirmed the corrected date carries no orphaned RSVPs from the old date

### Defect Fix: Printed Member Directory PDFs showed a stray scrollbar

**Problem:** Saving the printable Member Directory (`/members`, "Print Directory / Save as PDF") to
PDF showed a vertical scrollbar bar baked into every page of the output.

**Root Cause:** The directory sheet is taller than one screen, so it's a live scroll container on
screen. Chrome's print engine was rasterizing that container's scrollbar into the printed pages —
a rendering artifact, not real content; the actual page content and pagination were unaffected.

**Fix:** Suppressed the page's scroll container during print (`@media print`), which removes the
artifact without changing how content paginates across pages.

**Testing:**
- [x] Reproduced the scrollbar with a 40-member test directory, confirmed it disappears with the fix
- [x] Confirmed all pages and every entry still render correctly across the multi-page printout

## 1.68.0 — 2026-08-21

### Feature: The welcome packet, live under Club Records

**Value:** The club's annual welcome packet — service areas, committees, the year's calendar, how
to use the member portal — used to exist only as a file handed out once in September. A member who
joined in November, or who lost their copy, had no way to see it again.

#### What's New

- **The current welcome packet now lives at Club Records**, alongside meeting minutes and governing
  documents, readable by any linked member at any time — not just the room on the night it was handed
  out.
- **It's a living document.** An admin can update it or replace it for a new Lions year without a
  deploy — no file to email around, no PDF to re-upload.
- The printed handout itself is unchanged: a service program still prints the current packet, plus
  the year's two blank service-hour log sheets (now their own printable insert, so they can be
  reprinted mid-year without touching the whole deck).
- The printed directory is no longer bundled inside the welcome packet — a directory on paper goes
  stale the moment someone moves. The packet instead points members to the always-current directory
  on the portal, and notes that a limited number of printed copies are kept on hand for anyone who'd
  rather have paper.

#### Permissions

| Feature key | Required for |
|-------------|--------------|
| `welcome_packet.manage` | Creating, editing, or publishing a welcome packet at `/admin/welcome-packets` |

`welcome_packet.manage` is bound to the `admin` role only, by design — see `docs/decisions.md`
DECISION-090.

#### New Routes

- `/members/records/welcome-packet` — the current packet, member-facing
- `/admin/welcome-packets` — list, create, edit, and publish packets

### Defect Fix: Stray lines across printed PDFs

**Problem:** A member reported formatting issues — lines across the top and right — on the printed
member directory.

**Root Cause:** The browser's own "Headers and footers" print-dialog option, on by default in
Chrome/Edge/Safari, prints the page title, date, URL, and page number on every sheet. It isn't
something the app renders, and there's no CSS or JavaScript hook to suppress it — only the print
dialog's own toggle.

**Fix:** Added a short hint under the "Print / Save as PDF" button on the Member Directory, Monthly
Financial Statement, and Budget Worksheet pages, telling whoever's printing to uncheck "Headers and
footers" under More settings for a clean page.

**Testing:**
- [x] Reproduced the reported artifact with the browser's default print-header/footer settings on
- [x] Confirmed a clean page with "Headers and footers" unchecked
- [x] Confirmed the hint is hidden from the printed page itself (`print:hidden`)
