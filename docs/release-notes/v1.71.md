## 1.71.0 — 2026-09-04

### Security: Admin detail/edit pages now independently check permission, not just the admin layout

**Background:** A routine security review found that detail and "new" pages nested under several
admin areas — Members, Users, Events, Campaigns, Groups, Testimonials, Announcements — relied
only on the outer admin layout's coarse "holds *some* admin permission" check, rather than
checking their own specific permission the way every other admin page does. In practice, a
signed-in admin holding only one narrow permission (for example, managing testimonials) could
still open another member's detail page and see personal information — like a phone number or
home address — that their role was never meant to grant access to.

**Changes:**
- Every detail/edit page under those admin areas now checks its own required permission
  independently, matching the rest of the admin portal
- The automated check that guards against this class of gap now also covers nested detail/edit
  pages, not just each area's main listing page, so a future admin page can't reintroduce the gap
  unnoticed

Also corrects a data-type mismatch on meeting-minutes timestamps that had drifted out of sync
between the app's schema definition and the live database — no visible behavior change, but left
uncorrected it would have caused stored meeting times to be silently misread on a future deploy.

### Feature: Social Media Post Requests

**Value:** Members who want the club to post something to its social media accounts previously
had no consistent way to ask — requests arrived as scattered texts, emails, or in-person asks to
whoever happened to be around. This gives every member a single place to submit a request, gives
the board a dashboard to track and decide on it, and keeps a record of what was asked for and
what happened to it.

#### What's New

- **Submit a request** at `/members/social-requests/new` — choose the platform(s) to post to,
  write the post copy, optionally attach an image or a link, name a desired post date, and add
  any notes. Save as a draft and come back to it, or submit when ready.
- **Track your requests** at `/members/social-requests` — see every request you've submitted and
  its real status: still under review, Posted, Declined, or Deferred, not just "Submitted."
- A request can still be edited or withdrawn any time before the board acts on it; once decided,
  it's locked as a record.
- **Board review dashboard** at `/admin/social-requests` — the board sees every request, opens
  one to review the full detail, and records a decision (Posted, Declined, or Deferred) with an
  optional note. Every decision is kept permanently, so a request's full history is always
  visible — a later "Deferred" never erases an earlier one.
- Submitting a request automatically emails the board so nothing waits to be noticed.

#### Permissions

| Feature key | Required for |
|-------------|--------------|
| `social_requests.review` | Viewing the `/admin/social-requests` dashboard and recording a decision (granted to Admin and Board Member roles) |

Submitting and tracking a request requires only being a signed-in, linked club member — no
special permission needed.

#### New Routes

- `/members/social-requests` — your own requests and their status
- `/members/social-requests/new` — submit a new request
- `/members/social-requests/[id]` — view/edit a request, or see its decision history once decided
- `/admin/social-requests` — board review dashboard
- `/admin/social-requests/[id]` — review a request and record a decision
