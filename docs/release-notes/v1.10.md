## 1.10.1 — 2026-05-08

### Enhancement: Resilient Google Group Sync + Audit Log

**Value:** A single bad email (typo, deleted Gmail) used to halt the whole `club@` sync — every other change in that batch was silently dropped. Now bad addresses are logged and skipped, and **every** sync run (manual or auto-triggered by a member edit) is recorded with timestamp, triggering user, and the exact list of emails added / removed / failed. Admins finally have an audit trail for "who got removed last week and why."

**Changes:**
- Per-email try/catch in `syncClubMembersList` and `syncGoogleGroup` — one bad address no longer blocks the rest of the batch
- New `failed: { email, op, error }[]` field on `SyncResult`; surfaced as a yellow warning toast on the Sync club@ button
- Better error messages — Google's structured `response.data.error.message` is unwrapped instead of the generic `err.message`
- New `google_group_sync_log` table records every sync attempt: group email, triggering user, trigger source (manual / member_added / member_removed / member_updated), success flag, added / removed / failed lists, and any top-level error
- New `/admin/sync-log` admin page with per-group filter, pagination, and expanded view of each run's added / removed / failed lists
- Per-group sync error message now includes the failed email summary so it's visible in the group editor without re-running the sync

**Files Added:**
- `drizzle/migrations/0031_google_group_sync_log.sql` — new audit table with `created_at` + `(group_email, created_at)` indexes
- `src/app/(dashboard)/admin/sync-log/page.tsx` — admin sync log viewer

**Files Modified:**
- `src/lib/google-groups.ts` — resilient per-email loops, `SyncContext` parameter, `writeSyncLog` helper called on success and failure paths
- `src/lib/db/schema.ts` — `googleGroupSyncLog` table mapping
- `src/app/api/admin/members/sync-club/route.ts`, `src/app/api/admin/groups/[id]/sync/route.ts` — pass triggering user + `manual` source
- `src/app/api/admin/members/route.ts`, `src/app/api/admin/members/[id]/route.ts` — pass triggering user + `member_added` / `member_updated` / `member_removed` source
- `src/components/admin/sync-club-button.tsx` — yellow warning toast listing skipped emails
- `src/components/admin/admin-sidebar.tsx` — added "Sync Log" nav entry

## 1.10.0 — 2026-05-08

### Feature: Suggestion Box

**Value:** Members can now submit ideas for club activities or website/portal improvements directly from the member portal — with the option to remain anonymous. Submissions are emailed to `info@westervillelions.org` and are also captured in an admin-only triage view so nothing slips through the cracks.

#### What's New
- "💡 Suggestion Box" button on the `/members` portal banner opens a dialog with a category dropdown, message textarea, and an "Submit anonymously" checkbox
- Submissions are persisted to a new `suggestions` table and emailed to `info@westervillelions.org` via Resend
- When anonymous, the submitter's name and email are omitted from the email body and reply-to is suppressed
- New `/admin/suggestions` page lists incoming submissions with unhandled/all toggle, mark-handled, anonymous badge, and reply-by-email
- Admin sidebar gets a "Suggestions" nav entry (gated by the new `suggestions.view` feature, granted to `admin` and `board_member` roles) plus a footer launcher to submit a suggestion from inside admin
- Admin dashboard "Needs Attention" panel now surfaces an unhandled-suggestions tile linking to `/admin/suggestions`

#### Files Added
- `drizzle/migrations/0030_suggestions.sql` — `suggestions` table + `suggestions.view` feature seeded for `admin` and `board_member`
- `src/app/api/suggestions/route.ts` — `POST` handler that validates, persists, and emails submissions
- `src/app/api/admin/suggestions/[id]/route.ts` — `PATCH` handler to mark suggestions handled/unhandled
- `src/app/(dashboard)/admin/suggestions/page.tsx` — admin triage list view
- `src/components/suggestion-box-dialog.tsx` — Radix dialog for the submission form
- `src/components/suggestion-box-launcher.tsx` — small button wrapper that opens the dialog
- `src/components/admin/suggestion-mark-read-button.tsx` — optimistic mark-handled button

#### Files Modified
- `src/lib/db/schema.ts` — added `suggestions` table mapping
- `src/lib/permissions.ts` — added `SUGGESTIONS_VIEW` constant and description
- `src/app/members/page.tsx` — added Suggestion Box button to the portal banner
- `src/components/admin/admin-sidebar.tsx` — added "Suggestions" nav item and a launcher button in the sidebar footer
- `src/app/(dashboard)/admin/page.tsx` — added unhandled-suggestions tile to the "Needs Attention" panel
