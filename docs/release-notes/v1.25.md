## 1.25.1 — 2026-06-27

### Enhancement: Donor typeahead on the Acknowledgment dialog

**Value:** Recording an acknowledgment from the pending-acknowledgments queue no longer asks the treasurer to find and paste a donor's raw UUID. They now search by name or email and pick from a list — the same experience as the "Link donation" flow.

**Changes:**
- The "Record Acknowledgment" dialog's donor field is now a searchable typeahead (search by name or email, debounced) with a results dropdown; the selected donor shows as a labeled pill with a "Change" button.
- When the dialog opens with a donor already in context (from a donor's page or an already-linked transaction), it resolves and displays that donor by name instead of showing a blank field.
- Leaving the field empty still records the acknowledgment without linking a donor.

No schema changes, no new routes, no permission changes.

## 1.25.0 — 2026-06-26

### Feature: The Ledger — Increment 6a ("Donors, Acknowledgments & Dues→Admin Auto-Post")

**Value:** The final core increment of The Ledger. The Foundation can now keep proper donor records and issue the IRS-required acknowledgment letters, and membership dues now flow into the books automatically instead of being re-entered by hand.

#### What's New

- **Donor records** (`/admin/ledger/donors`) — track donors (name, email, address, optional link to a member) and see each donor's giving history. Donor contact information is restricted to treasurers and admins; board members see only the acknowledgment activity, not donor identities.
- **Acknowledgment tracking** — link a Foundation donation to a donor and record the IRS acknowledgment: a written acknowledgment for gifts of **$250+**, or a quid-pro-quo disclosure when goods/services worth **$75+** were given in return (the type is determined automatically from the amounts, with an override). Record it as sent and attach the letter (paste the text or upload the file) — private, served only through an authenticated link.
- **Dues → ledger auto-post** — recording a membership dues payment now automatically posts the income to the Club's Administrative fund (category "Club dues"), so the books stay current with no double entry. Editing a dues payment updates the ledger entry; deleting it removes the entry. If the linked ledger entry has already been reconciled, the dues change is allowed but the entry is flagged out-of-sync (shown as a warning on the ledger overview) rather than silently altered. If the auto-post ever can't complete, the dues payment is still saved and you're prompted to record the income manually — a dues payment is never lost.

#### Permissions

No new permission key. Donor records and acknowledgment management use `ledger.record` (treasurers + admins); donor deletion uses `ledger.manage`; the acknowledgment queue summary is visible with `ledger.view` (without donor identities).

#### New Routes

- `GET /admin/ledger/donors`, `GET /admin/ledger/donors/[id]`
- `GET·POST /api/admin/ledger/donors` (+ `GET·PATCH·DELETE /[id]`)
- `POST·PATCH /api/admin/ledger/transactions/[id]/acknowledge`
- `GET /api/admin/ledger/acknowledgments` (+ `/[id]/letter` upload/stream)

#### The Ledger is now feature-complete

This closes the six-increment build: Books, Controls + Reimbursements, Compliance & 990, Reports, the member Impact dashboard, and now Donors/Acknowledgments + the dues auto-post. The one remaining optional piece is the **Zeffy income integration** (6b), which is deferred until a Zeffy API key is registered.
