## 1.2.4 — 2026-03-26

### Defect Fix: /join page redirected to sign-in for unauthenticated visitors

**Problem:** Prospective members visiting `/join` were redirected to the sign-in page, blocking the membership application entirely.
**Root Cause:** `/join` was missing from the `publicPaths` allowlist in `src/proxy.ts`.
**Fix:** Added `/join` to the public paths list.

## 1.2.3 — 2026-03-26

### Feature: Last login tracking and user activity filter

**Value:** Admins can now see who has actually logged into the portal and filter down to users who have never activated their accounts — useful for follow-up outreach.

**Changes:**
- New `last_login_at` column on `users` table, updated on every sign-in via a fire-and-forget write in the NextAuth JWT callback
- Admin users table shows a "Last Login" column with formatted date/time or "Never"
- New "Login Activity" filter dropdown: All / Has logged in / Never logged in

## 1.2.2 — 2026-03-26

### Enhancement: Inline position editing in group membership table

**Value:** Admins can update a member's position directly in the group edit page without removing and re-adding them.

**Changes:**
- Clicking a position in the membership table enters edit mode — shows a dropdown (if the group has `availablePositions`) or a free-text input
- Save/Cancel buttons commit or discard the change inline
- A pencil icon appears on hover to hint the field is editable
- New `PATCH /api/admin/groups/[id]/members` endpoint updates `position` on a membership record

## 1.2.0 — 2026-03-26

### Feature: Member Profile Pictures

**Value:** Makes the member directory and public About page leadership section more personal and human. Visitors and prospective members can connect faces to names, increasing trust and community feel.

#### What's New

- **Profile photo upload** — Members can upload a photo from their profile page (`/members/profile`); admins can manage any member's photo from the admin member edit page
- **Client-side crop** — Upload dialog includes a square crop UI (powered by `react-image-crop`, already a project dependency) before saving; output compressed to JPEG ≤ 300 KB
- **Photo storage** — Photos stored as base64 data URIs in the new `members.profile_picture` column (TEXT, nullable)
- **Member directory** — Each member card in the portal shows a 48px circle avatar (photo or shadow silhouette)
- **About page leadership** — Leadership grid shows a 64px circle avatar per board member, served via a public photo endpoint (avoids inlining large base64 in HTML)
- **Shadow avatar fallback** — Gender-neutral inline SVG silhouette shown when no photo is present — no external image dependency, no broken image flash
- **Public photo endpoint** — `GET /api/public/members/[id]/photo` serves member photos as proper image responses with `Cache-Control: public, max-age=3600`; used by the About page
- **Seed data** — Board of Directors members seeded with famous-person example photos (gender-matched): Lincoln, Roosevelt, Einstein, Franklin, Washington, Twain / Curie, Earhart, E. Roosevelt, Parks
