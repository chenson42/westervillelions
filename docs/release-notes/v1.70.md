## 1.70.0 — 2026-09-01

### Feature: Cash & Bank Accounts summary on the admin Ledger dashboard

**Value:** A fund's books tying out to the bank isn't the same thing as every individual account
being correct or even visible — the club's petty cash box (about $250 in physical cash) turned
out to have been folded, untracked, into the Administrative Fund's starting balance since day
one, with no line of its own anywhere. Finding it took a manual database search; nothing on the
dashboard would ever have surfaced it.

#### What's New

- `/admin/ledger` now shows a **Cash & Bank Accounts** panel — every active bank account for
  both the Club and the Foundation (checking, savings, petty cash), grouped by entity, with its
  real running balance
- Each account now carries its own starting balance, the same way each fund already does, so its
  balance is accurate on its own — not just as part of a fund total

#### New Routes

None — this extends the existing `/admin/ledger` dashboard.

## 1.70.1 — 2026-09-03

### Defect Fix: Homepage "Upcoming Events" card showed a recurring event's series start, not its next date

**Problem:** A recurring event on the homepage — for example the Farmers Market — always showed
its very first occurrence date on the "Upcoming Events" card, even long after that date had
passed.

**Root Cause:** The card correctly *sorted* recurring events by their next upcoming occurrence,
but computed that date only for sorting and then discarded it — the displayed date still came
from the event's original series-start date.

**Fix:** The homepage now keeps the computed next-occurrence date and displays it directly,
instead of re-reading the event's original start date.

**Testing:**
- [x] Automated regression test confirming the display date is the upcoming occurrence, not the
  series start, for a weekly recurring event
- [x] Confirmed non-recurring events and the public/member Events pages are unaffected
- [x] Typecheck, full unit test suite, and production build all pass

Also patches two high-severity CVEs (`browserslist`, via `autoprefixer`/Next.js's build tooling)
found by the routine `pnpm audit` gate ahead of this push.

## 1.70.2 — 2026-09-03

### Defect Fix: Same-day events disappeared from every event listing (and could be rejected from RSVP) hours before they actually happened

**Problem:** Today's General Meeting — and any event later the same day — could silently vanish
from the homepage, the public and member Events pages, the admin Events pages, and the "next
meeting" lookup used for meeting minutes, hours before it actually occurred. In the same window,
signing up for a same-day occurrence could be wrongly rejected as "a past occurrence."

**Root Cause:** Every one of these surfaces decides whether an event is upcoming by comparing it
against "right now." That comparison read the server's clock through its local timezone — and
this app's production server runs in UTC, not Eastern time, while every event's stored time
means Eastern local time. For several hours out of every day (the gap between UTC and Eastern),
the server's read of "now" was several hours ahead of true Eastern time, so anything scheduled
in that gap looked like it had already happened.

**Fix:** Every one of those surfaces — plus event RSVP — now reads "the current time" as true
Eastern local time, regardless of what timezone the server itself is running in, so an event's
scheduled time and "now" are always compared on the same clock.

**Testing:**
- [x] Confirmed live on the production site before the fix: today's 7:00 PM General Meeting was
  missing from the public Events page mid-afternoon
- [x] Automated regression tests covering the timezone conversion directly, including daylight
  saving transitions
- [x] Typecheck, full unit test suite, and production build all pass
