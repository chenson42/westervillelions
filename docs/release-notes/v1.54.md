## 1.54.0 — 2026-07-30

### Feature: Transactions can be tied to a specific budget line item (B-30)

**Value:** Until now, budget-vs-actual at the line-item grain was stitched together by a fuzzy string
match (category + cause + party ≈ line label) — which silently missed real spending when names drifted
(e.g. a "Pilot Dogs" budget line vs. a "Pilot Dogs, Inc." transaction). Transactions can now be
**explicitly linked** to the budget line they apply to, making budget-vs-actual exact.

#### What's New
- **Budget-line picker** on the transaction form *and* the reimbursement "mark paid" flow — choose the
  budget line a transaction applies to; it auto-fills the category and cause. (Also fixed: the
  beneficiary-cause field can now be edited after creation, not only when first entered.)
- **Exact budget-vs-actual** — a linked transaction attaches to its budget line precisely. The old
  fuzzy match survives only as a clearly **flagged, footnoted fallback** for un-linked rows, and a
  linked transaction is never also fuzzy-counted (no double-counting).
- **Fiscal-report cause/line breakdown** — the member Statement of Financial Condition and the admin
  Fund Report now break each category down to its **causes and line items**, with an **"Other"
  catch-all** row so the lines always foot to the category total, and **all-zero rows omitted**.
- **Guardrails** — editing a linked transaction's category auto-clears the now-stale link (with a
  notice) instead of blocking the edit; collapsing a budget breakdown that still has linked
  transactions warns with the real linked-transaction count.

#### Backfill
A one-time backfill links historical transactions to their budget lines where an unambiguous match
exists, and **reports** the ones it can't (name drift, no budget) for manual resolution — it never
guesses.

#### Schema
New nullable `ledger_transactions.budget_line_id` FK (migration `0072`).

#### Permissions
Unchanged — `ledger.record` gates the pickers; report surfaces unchanged.

#### Known follow-up
In a rare fiscal-year-boundary edit, a stale link still clears correctly but the notice toast doesn't
fire (cosmetic, no data impact). Tracked as a small follow-up.
