## 1.24.1 — 2026-06-26

### Maintenance: 30-day code + dependencies review fixes

**Background:** The monthly code and dependencies reviews (`docs/reviews/2026-06-26-*.md`) came back clean on auth/invariants (0 high code findings) but surfaced one correctness defect, some duplication, and dependency hygiene worth clearing before the final Ledger increment.

**Changes:**
- **Defect fix (990 determination):** the 990-prep export now feeds `determine990` the fiscal-year **ending** balance (was the opening balance), so the determined return matches the overview and compliance pages for the same entity/year.
- **Dependency CVEs cleared:** `pnpm.overrides` for `postcss` and `qs` resolve the two transitive moderate advisories; `xlsx` removed from the toolchain (the two import scripts migrated to `exceljs`), clearing two dev-tree high advisories. Production audit remains clean (0 high/critical).
- **Safe bumps:** Next.js 16.2.6→16.2.9, plus React, Radix, `@vercel/blob`, `resend`, `googleapis`, `date-fns`, and others to current patch/minor. Removed the unused `next-themes` dependency.
- **Code cleanups:** compliance guardrail flags now come from the single canonical `guardrails()` helper (no duplicated logic); the impact page skips an unneeded permission lookup when the dashboard is open to all members; reimbursement tab counts use one grouped query; the unsafe CSV cell helper renamed for clarity.

No schema changes; no behavior change for users beyond the corrected 990 figure.

## 1.24.0 — 2026-06-26

### Feature: The Ledger — Increment 5 ("Philanthropy / Impact Dashboard")

**Value:** Gives board members and (optionally) all club members a compelling, single-page view of what the Westerville Lions have accomplished for the community — total giving all-time and this fiscal year, a breakdown of giving by cause, a fiscal-year-by-year history, and a list of recent named grant recipients. The admin controls whether the dashboard is board-only or open to all members without a code change.

#### What's New

- **Community impact dashboard** (`/members/impact`) — aggregate philanthropy data drawn from the Activity (club) and Charitable/Scholarship (foundation) funds. Headline all-time and current-fiscal-year giving totals, a horizontal bar list broken down by cause, a fiscal-year table, and a "Recent Named Gifts" section naming grant recipients (e.g., "Westerville Food Pantry").
- **Member-dues firewall:** the Administrative fund — where member dues are held — is categorically excluded at the database query layer. Member dues money never appears as "philanthropy" under any circumstance.
- **Two-tier visibility gate:** when `philanthropyVisibility = 'board'` (the default), only board members, the treasurer, and admins can see the dashboard. When an admin flips the toggle to `'members'` on the Ledger Settings page, any signed-in member with a linked account can view it — no code change or redeployment needed.
- **"Our Impact" card** added to the member portal hub (`/members`), visible to all signed-in members.

#### Permissions

| Feature key | Required for |
|-------------|--------------|
| `impact.view` | View the philanthropy dashboard when `philanthropyVisibility = 'board'`; not required when visibility is `'members'` |

Default role bindings: `admin` (automatic — admin receives all features), `treasurer`, `board_member`. The `member` and `volunteer` roles do not receive `impact.view`; the visibility setting is what opens the dashboard to them.

#### New Routes

- `GET /members/impact` — philanthropy and community impact dashboard (authenticated, member portal)
