## 1.5.2 — 2026-04-06

### Enhancement: Announcements UX Polish, Delete Support, ConfirmDialog Standard

**Value:** Announcements card now visually matches event cards; admins can delete announcements; all destructive actions use a styled modal instead of the browser's native confirm dialog.

**Changes:**

- **Announcements card:** `rounded-xl border border-gray-200 shadow-sm` → `rounded-2xl shadow-lg` — matches event card visual weight. Added gold "Announcements" badge above the card to mirror the "Upcoming Events" badge. Removed internal "Announcements" heading. Padding bumped to `px-8 py-5`.
- **Delete announcements:** Delete button (with confirmation dialog) added to the admin announcements list.
- **ConfirmDialog component:** New shared `src/components/ui/confirm-dialog.tsx` using Radix AlertDialog — styled modal with Cancel / Confirm buttons and a `destructive` variant (red confirm button).
- **All `window.confirm()` calls replaced** across the codebase: announcements delete, testimonials delete, group delete, event delete.
- **CLAUDE.md:** Added "Confirm / Destructive Actions" section explicitly banning `window.confirm/alert/prompt` and documenting the `ConfirmDialog` pattern.

## 1.5.1 — 2026-04-06

### Enhancement: Multiple Users Per Member; Auto-Match @westervillelions.org Sign-Ins

**Value:** Members with multiple email addresses (personal Gmail + club email) can now all link to the same member record. Members signing in with their `@westervillelions.org` Google account are matched and linked automatically by name.

**Schema change:** FK moved from `members.user_id` to `users.member_id` — multiple user accounts can now reference one member (many-to-one). Migration 0023 copies existing links and drops the old column.

**Auto-match logic:** On first sign-in with a `@westervillelions.org` Google account, the JWT callback splits the display name into first/last and queries members case-insensitively. If an unambiguous match is found with no existing conflict, the user is linked immediately — no admin action needed.

**Guard rails:** Skips if user already linked; skips if another user owns that member record; fire-and-forget so a failed match never blocks sign-in.

## 1.5.0 — 2026-04-06

### Feature: Testimonials, Admin Users Overhaul, Unlinked User Alerts

**Value:** Social proof on the Join page increases membership conversion. Admins now have clear visibility into unlinked user accounts and meaningful account type information.

#### Testimonials

- New `testimonials` table + migration (0022) with Lori Lampel seed row
- Admin CRUD at `/admin/testimonials` — board members and admins can create, edit, reorder, activate/deactivate, and delete
- Auto-advancing carousel on `/join` between the benefit cards and the application form (6s interval, prev/next arrows, dot indicators, pauses on hover)
- Section hidden when no active testimonials exist

#### Admin Users Page Overhaul

- **Account Type column** replaces the meaningless "Verified/Unverified" (emailVerified) status — shows Google (with G logo) or Password badge based on OAuth provider
- **Member Record column** — green "✓ [name]" if linked, amber "⚠ Not linked" if not
- Amber warning banner at top of page counts unlinked users needing review
- Unlinked rows highlighted with amber row tint

#### Unlinked User Email Alert

- When a Google user signs in and has no member record, an email fires to `info@westervillelions.org` with name, email, and a direct link to Admin → Users (fire-and-forget)
