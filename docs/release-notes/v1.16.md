## 1.16.0 — 2026-05-20

### Feature: "Add to Calendar" Provider Dropdown

**Value:** The v1.15.0 "Add to Calendar" button downloaded a `.ics` file with no context, which on Windows or Android can feel like a mystery file. The new dropdown shows recognizable calendar brands so users can pick where the event goes — Google Calendar opens directly in the browser with the event pre-filled, while Apple Calendar and the universal `.ics` option still work for everyone else.

#### What's New

- **Provider dropdown** replaces the single-action button on public and member event surfaces. Trigger label stays "Add to Calendar" with a chevron-down icon.
- Four menu items per dropdown:
  - **Google Calendar** — opens `calendar.google.com` in a new tab with the event pre-filled.
  - **Apple Calendar** — downloads the same `.ics` macOS and iOS recognize natively.
  - **Outlook** — opens `outlook.live.com` in a new tab with the event pre-filled.
  - **Download .ics** — universal fallback that works with any calendar app.
- **Series-level button** (on recurring events): Google/Outlook items target the **next upcoming occurrence** with a "(next occurrence only)" label, since web deeplinks can't represent a multi-occurrence series; Apple Calendar and Download .ics still deliver the full series in one file.
- **Disabled state** when a recurring series has no upcoming occurrences: Google/Outlook items fade with a "No upcoming occurrences" tooltip; Apple/`.ics` items remain active (the historical series is still useful).
- **Timezone-safe URLs.** Google and Outlook deeplinks now correctly convert wall-clock Eastern times to UTC, handling DST for both summer (EDT, UTC-4) and winter (EST, UTC-5) events.
- **All-day events** use Google's exclusive end-date format (`dates=YYYYMMDD/YYYYMMDD+1`) and Outlook's `allday=true` parameter.
- **Description handling:** truncated to 1,000 characters with a "see the full event details at…" footer linking back to the event page. Null description and location fields are omitted from the URL entirely (no `description=null`).

#### Permissions

| Feature key | Required for |
|-------------|--------------|
| (none new) | Same as v1.15.0 — public events anonymous; private events reuse `members.view`. |

#### Compatibility

- The existing `GET /api/events/[id]/ics` endpoint is unchanged. Bookmarks and any external integrations that hit it directly continue to work.
- The old `<AddToCalendarButton>` component was replaced by `<AddToCalendarDropdown>`; the unused `eventTitle` prop from v1.15.0 is removed.
