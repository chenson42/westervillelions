## 1.11.0 — 2026-05-08

### Feature: Custom RSVP Question + RSVP UX Overhaul

**Value:** Events can now ask attendees one optional question at RSVP/signup time (e.g. "What dish are you bringing?" for potlucks, "T-shirt size?" for service events). The RSVP form on the public event page is also clearer — picking a status no longer instantly saves; users now click an explicit **Submit RSVP** button. Attendee totals across the public and admin views finally include guests, so a 30-spot event with 28 RSVPs and 5 guests correctly reports 33 — and rejects further signups.

#### What's New

**Custom RSVP question (per event, optional)**
- Admin event form has a new "Custom RSVP question" card: type the prompt, choose Free text or Pick-one (dropdown), optionally mark required. Dropdown takes one option per line.
- Question and answer flow through every RSVP/signup surface: authenticated RSVP form, anonymous public RSVP, single-event signup button, and the per-occurrence signup list for recurring events.
- Server validates required answers and (for select type) that the answer is one of the configured options.
- Admin RSVP tables (flat and per-occurrence) get a new column titled with the question label, showing each attendee's answer.

**Clearer RSVP submission**
- Authenticated RSVP form now has explicit submit semantics: Attending / Maybe / Decline buttons select a draft, and a prominent "Submit RSVP" button (or "Update RSVP" when something changed) saves it.
- Saved state is shown via a green "✓ You're attending" indicator next to a disabled "RSVP saved" button.
- New "Remove RSVP" link cancels a saved RSVP without using browser confirms.

**Guests counted in attendee totals**
- Public event page: per-occurrence count and single-event count now sum `1 + guestCount` per non-declined RSVP. Labels read "X attendees (incl. guests)" / "X of Y spots filled (incl. guests)".
- Admin event detail (non-recurring): the green Attending card shows the headcount with a "N members + M guests" subtitle breakdown.
- Admin event detail (recurring): each occurrence's collapsed header shows total headcount with "(incl. guests)" suffix.
- Signup cap check (`/api/events/[id]/signup`) now rejects when `total RSVPs + guests >= maxAttendees`, matching the displayed numbers.

**Form bug fix**
- Admin event form: title input and other text fields no longer flicker between controlled/uncontrolled state. `handleChange` keeps text values as strings instead of coercing `""` to `null`; the API still normalizes empty strings to null on save.
