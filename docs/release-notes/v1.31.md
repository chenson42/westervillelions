## 1.31.2 — 2026-07-21

### Defect Fix: Broken "Pending Member Applications" Link

**Problem:** Clicking the amber "Pending Member Applications" chip on the admin
dashboard led to an error page instead of the applications list.

**Root Cause:** The chip pointed at a route that never existed
(`/admin/applications`); the page shipped at `/admin/membership`. The dead link
dates back to v1.3.2 and went unnoticed because applications are infrequent.

**Fix:** The chip now links to Admin → Membership.

**Testing:**
- [x] Chip navigates to the membership applications page
- [x] No other references to the dead route exist

## 1.31.1 — 2026-07-21

### Enhancement: Cleaner Gift-Detail Layout (Community Impact)

**Value:** Expanded gift rows showed the recipient floating mid-row between the
date and amount, so every row's text landed in a different spot — hard to scan.

**Changes:**
- Each gift now reads as one left-aligned stack: recipient first (bold), the
  gift's description beneath it, and the date last in light gray — with the
  amount alone on the right. The whole list scans down a single axis.

## 1.31.0 — 2026-07-21

### Feature: Transaction Receipts (The Ledger)

**Value:** The compliance dashboard warned about expenses missing receipts, but
there was no way to attach one — the warning pointed at a field no screen could
fill. Now every expense can carry its receipt, and rows that will never have
one can be formally waived instead of nagging forever.

#### What's New

- Attach a receipt (photo or PDF) to any expense — while recording it or on an
  existing transaction. On a phone, the picker opens the camera, so you can
  snap the receipt at the register.
- Photos are automatically scaled down before upload (longest edge 1600px) —
  small enough to store cheaply, still legible for line items.
- View, replace, or remove a receipt from the transaction form; receipts
  stream through a permission-gated viewer, never a public URL.
- **Waivers for historical rows:** rows with no obtainable receipt (like the
  imported Quicken history) can be marked "no receipt available" with a
  required reason — recorded with who waived it and when. Waived rows stop
  counting toward the compliance warning, so the count can genuinely reach
  zero. Waiving requires the ledger-manage permission, a deliberately higher
  bar than day-to-day recording.
- **The compliance warning is now a link** — it opens a new all-funds register
  view filtered to exactly the expenses still missing receipts.

#### Permissions

Existing keys only: `LEDGER_RECORD` to attach/replace/remove, `LEDGER_VIEW` to
view a receipt, `LEDGER_MANAGE` to waive.

### Feature: Public Gift Descriptions (Community Impact)

**Value:** A gift's payee often doesn't say what the gift did — "$400 to The
City of Westerville" doesn't tell members it sponsored the Arborfest. The
treasurer can now add a short public description to any gift, shown on the
Our Community Impact page, while internal memos stay private.

#### What's New

- New optional "Public description" field on expense transactions (create and
  edit), capped at 200 characters.
- Descriptions appear under the gift in both the cause drill-down and Recent
  Named Gifts; gifts without one look exactly as before.
- Internal memos are never shown to members — the public description is a
  separately curated field.
- Launch content included: the treasurer curated descriptions for all 51
  current gifts (scholarship schools, program sponsorships, disaster-relief
  context, and partner-organization missions), applied alongside this release.

### Defect Fix: Receipt Files Could Stream Corrupted Bytes

**Problem:** Viewing a very small receipt file (under ~4 KB) could return
garbage bytes instead of the file — and could break the next request on the
same connection. This affected the existing reimbursement receipt viewer as
well as the new transaction receipt viewer.

**Root Cause:** The response streamed the file buffer's underlying memory
allocation, which for small files is a shared pool containing unrelated data —
an inherited pattern from the original reimbursement implementation.

**Fix:** Both viewer routes now copy exactly the file's own bytes into the
response, with a regression test that reconstructs the precise failure shape.

**Testing:**
- [x] Byte-for-byte comparison of uploaded vs streamed files on both routes
- [x] Keep-alive connection integrity verified across sequential requests

### Enhancement: Quieter Cause Expansion (Community Impact)

ring — the details sliding open or closed is the feedback. Keyboard users
still get the focus ring for accessibility.

**Changes:**

  mouse or touch taps.
