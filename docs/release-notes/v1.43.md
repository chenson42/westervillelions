## 1.43.0 — 2026-07-28

Lets you reconcile a single bank deposit or payment that your books recorded as
several separate transactions — the piece that was blocking months from closing.

### Feature: Batch Bank Reconciliation

**Value:** The bank often shows **one** line for money your books recorded as **many**
transactions — most commonly a **weekly Zeffy dues deposit** that bundles a batch of
individual member payments, but also fundraiser deposits and split-purchase payments.
Until now the reconciliation workbench could only match one bank line to one ledger
transaction, so those deposits couldn't be reconciled — and a month couldn't close (or
publish its member statement) while they sat unmatched. This adds many-to-one matching.

#### What's New

- **Match several transactions to one bank line.** In the reconciliation matching view,
  select any set of unreconciled transactions whose amounts **sum exactly** to a bank
  line, and commit them as a single match. A running **"selected vs. line amount"**
  indicator turns green when they balance; the commit button stays disabled until they
  do — so a batch can never be off by a cent.
- **Works for income and expense.** It's a general capability, not dues-specific: a
  credit line matched to several deposits, or a debit line matched to several expense
  rows (a split purchase), both work. A payment-method filter and date/amount sort help
  you cluster a week's rows, but never hide anything.
- **See and adjust a batch.** A batched bank line shows **"Matched · N"** and expands to
  list its transactions, each with its own **Unmatch** — so you can correct one row
  without redoing the whole batch.
- **Tie-out stays correct.** A batched line counts once toward the session's cleared
  total (a subtle bug that would have inflated the tie-out was found and fixed), so the
  balance-to-the-penny close gate still works with batch matches.
- **Months publish while dues are in transit.** Because dues are recorded when a member
  pays but reach the bank in the next weekly Zeffy deposit, a recently-recorded,
  not-yet-deposited dues batch no longer blocks its month's statement from publishing —
  while a *stale* un-deposited batch still flags the month, so a neglected sync isn't
  hidden.

#### Permissions

| Feature key | Required for |
|-------------|--------------|
| `ledger.record` | Creating and removing matches (same permission as all reconciliation) |

_No new permission key; no database changes._

#### Routes

- `POST /api/admin/ledger/reconciliation/sessions/[id]/match` — now accepts a set of
  transaction IDs for one bank line (exact-sum validated server-side)
