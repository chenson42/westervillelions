## 1.34.0 — 2026-07-21

### Defect Fix: Receipt Uploads Failed in Production

**Problem:** Uploading a receipt on the live site failed with "Failed to
upload receipt," even though the photo had converted correctly. This affected
every receipt and reimbursement upload in production, not just one file.

**Root Cause:** Receipt files were being stored on the hosting platform's
local disk, which is read-only in production — so every save threw an error.
(The intended production store, an external file service, was never
configured, and the code silently fell back to the disk write that can't
work there.)

**Fix:** Receipt and reimbursement files — and gift acknowledgment letters —
are now stored directly in the club's database, alongside the rest of your
data. This removes the external file service entirely: there's nothing to
configure, no separate storage account or spending cap to manage, and the
files are included in the same backups as everything else. The upload that
was failing now succeeds.

**Also fixed along the way:**
- Removing or replacing a receipt now actually deletes the old file, instead
  of leaving orphaned data behind.
- A file-corruption safeguard that protected two of the four "view receipt"
  screens now protects all four.

**Testing:**
- [x] Full upload → view → replace → delete cycle exercised against a real
  database in production mode; viewed files come back byte-identical to what
  was uploaded
- [x] Replacing a receipt confirmed to delete the prior file from the database
- [x] All 459 unit tests, typecheck, production build, and end-to-end suite green

**Note:** No existing receipts needed to be moved — there were none stored in
production, since uploads had been failing.
