## 1.7.1 — 2026-04-13

### Feature: Public RSVP on Event Detail Pages with Optional Guest Count

**Value:** Anyone with an event link can now RSVP without creating an account. Private events are still hidden from the public events listing, but anyone with the direct link can view and RSVP — useful for sharing invites externally.

#### What's New

- **No login required to RSVP** — anonymous users provide name + email; returning anonymous users update their RSVP by matching email
- **Private events accessible via direct link** — `/events/[id]` no longer requires `isPublic = true`; the listing page still filters to public only
- **Guest count field** — new per-event `allowGuestCount` setting; when enabled, the RSVP form shows a guest count input for "Attending" responses
- **Logged-in members** see the 3-button RSVP interface with optional guest count
- **Anonymous users** see a name + email form with status buttons and optional guest count, followed by a confirmation message
- **Admin event form** — new "Allow guest count" checkbox in the Settings section
- **Admin event detail** — anonymous RSVPs appear in the RSVP table with a `(guest)` tag

#### Files Added
- `drizzle/migrations/0026_public_rsvp.sql` — adds `rsvp_name`, `rsvp_email` to `event_rsvps`; makes `user_id` nullable; adds `allow_guest_count` to `events`
- `src/components/public/public-rsvp-form.tsx` — client component handling both logged-in and anonymous RSVP

#### Files Modified
- `src/lib/db/schema.ts` — `eventRsvps.userId` nullable; added `rsvpName`, `rsvpEmail`; added `allowGuestCount` to `events`
- `src/app/api/events/[id]/rsvp/route.ts` — POST/DELETE now support unauthenticated requests
- `src/app/events/[id]/page.tsx` — removed `isPublic` filter; renders `PublicRsvpForm` when `requiresRsvp` is true
- `src/components/admin/event-form.tsx` — added `allowGuestCount` checkbox
- `src/app/api/admin/events/route.ts` — `allowGuestCount` saved on create
- `src/app/api/admin/events/[id]/route.ts` — `allowGuestCount` saved on update
- `src/app/(dashboard)/admin/events/[id]/page.tsx` — left join for anonymous RSVPs; `(guest)` tag

## 1.7.0 — 2026-04-12

### Feature: Auto-Sync board_member Role with Board of Directors Group

**Value:** Board members previously had to be manually given the `board_member` role separately from being added to the Board of Directors group. This caused the role to drift out of sync. Now it's automatic — adding someone to the board assigns the role, removing them revokes it.

#### What's New

- **Automatic role assignment** — When a member is added to the "Board of Directors" group, their linked user account is automatically assigned the `board_member` role (if they have one)
- **Automatic role removal** — When a member is removed from the group, the `board_member` role is revoked
- **Sync endpoint** — `POST /api/admin/groups/sync-board-role` assigns/removes the role for all current board members in bulk
- **Sync button** — "Sync Board Member Role" button appears on the Board of Directors group admin page for manual re-sync
- **One-time sync ran** — 9 board members were assigned the `board_member` role on deploy; 3 already had it; 0 removed

#### Files Added
- `src/app/api/admin/groups/sync-board-role/route.ts` — bulk sync endpoint (admin only)
- `src/components/admin/sync-board-role-button.tsx` — client component for sync button
- `scripts/sync-board-role.ts` — reusable one-time sync script

#### Files Modified
- `src/app/api/admin/groups/[id]/members/route.ts` — added `syncBoardMemberRole()` helper on POST/DELETE
- `src/app/(dashboard)/admin/groups/[id]/page.tsx` — renders sync button when viewing Board of Directors
