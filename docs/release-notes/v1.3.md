## 1.3.4 — 2026-04-03

### Security: CAPTCHA protection for newsletter and membership application forms

**Problem:** The newsletter subscription and membership application forms had no bot protection, allowing automated submissions to pollute the newsletter list and application queue.

**Fix:** Added Cloudflare Turnstile CAPTCHA to both forms, matching the existing pattern already in place on the contact form. The submit button is disabled until the CAPTCHA completes. On error or expiry, the widget resets and the token is cleared. Server-side verification is enforced in both API routes — requests without a valid token are rejected with a 400 error.

**Files Modified:**
- `src/components/newsletter-form.tsx` — Turnstile widget added
- `src/components/membership-application-form.tsx` — Turnstile widget added
- `src/app/api/newsletter/subscribe/route.ts` — Server-side CAPTCHA verification
- `src/app/api/membership-applications/route.ts` — Server-side CAPTCHA verification

## 1.3.3 — 2026-03-31

### Defect Fix: Content corrections and minor UI improvements

**Problem:** Several pieces of content were inaccurate or missing: the club's founding year was listed as 1938, the mailing address was absent from the Connect page, the meeting schedule was incorrect, and the leadership profile pictures were too small.

**Root Cause:** Original content was carried over from placeholder/estimated data and had not been verified against club records.

**Fix:**
- Corrected founding year from 1938 → 1928 across all pages
- Added PO Box mailing address to the Connect page
- Updated meeting schedule to Thursdays, September–May
- Removed redundant "Our Service Areas" section from the public events page
- Increased leadership profile picture size from 96px → 128px for better readability

**Files Modified:**
- `src/app/about/page.tsx` — Founding year corrected
- `src/app/contact/page.tsx` — PO Box address added
- `src/app/events/page.tsx` — Removed "Our Service Areas" section
- `src/app/layout.tsx` — Founding year corrected
- `src/app/meetings/page.tsx` — Meeting schedule updated
- `src/app/page.tsx` — Founding year corrected
- `src/components/layout/footer.tsx` — Founding year corrected
- `src/components/members/leadership-avatar.tsx` — Profile picture size increased

## 1.3.0 — 2026-03-26

### Feature: Event RSVP Configuration and Admin Viewer

**Value:** Admins can now mark specific events as requiring RSVPs and view attendance details — who is coming, how many guests — directly from the event admin page. Non-RSVP events remain unchanged.

#### What's New

- **Requires RSVP toggle** — Each event has a new "Requires RSVP" checkbox on the admin create/edit form
- **RSVP badge** — Events list in admin shows a blue "RSVP" badge on events that require RSVPs
- **RSVP Details section** — Admin event detail page shows a summary card (Attending / Maybe / Declined / Total Guests) and a full attendee table with response status, guest count, and response date
- **Backward compatible** — Existing events default to `requires_rsvp = false`; no disruption to existing data

#### Files Added

- `drizzle/migrations/0012_events_requires_rsvp.sql` — Idempotent migration adding `requires_rsvp BOOLEAN NOT NULL DEFAULT false` to events

#### Files Modified

- `src/lib/db/schema.ts` — Added `requiresRsvp` to events table
- `src/components/admin/event-form.tsx` — Added "Requires RSVP" checkbox
- `src/app/api/admin/events/route.ts` — POST handler reads `requiresRsvp`
- `src/app/api/admin/events/[id]/route.ts` — PATCH handler reads `requiresRsvp`
- `src/app/(dashboard)/admin/events/[id]/page.tsx` — RSVP Details section with summary counts and attendee table
- `src/app/(dashboard)/admin/events/page.tsx` — Blue "RSVP" badge on events with `requiresRsvp = true`
